5.14集中探讨之后的进展：

（1）发现的问题
1.我们在之前的测试中认为仅仅处理已有的视频并不具备很好的实践意义，于是想要将程序与摄像头连接具备可以处理实时视频的功能，但如果连接电脑的摄像头，视角太局限，而且不易移动。
2.在开始着眼于手机摄像头后，我们发现有一个问题在于因为模型和代码文件都是在电脑环境中完成的，所以如果贸然一味地照搬过去，环境生态是不一样的，这一方法是行不通的。
3在试运行开始拍摄后，我们在拍摄途中首先发现程序对于具体物体的识别方面依旧不够准确，例如在拍摄途中遇到了在面前有桌子和墙壁的情况下依然不给出停下或转弯的反馈，在墙壁在左，椅子在墙壁右边的情况下，程序给出向左绕行的反馈。
4.除此之外，在复盘逐帧分析视频的时候我们还发现在某几个时刻，程序会突然给出向左或向右闪躲的指令，以及当面前出现台阶的时候，它并不会给出向上或向下的指令反馈。

（2）针对这些问题我们的解决方案和思考
1.针对电脑摄像头的问题，我们认为可以无法识别改变应用场景，研究一下在手机上运行的可能性，因为手机摄像头操纵的灵活性更高以及日常使用中的泛用性更广。
2.针对生态不同这一点，我们经过思考决定将手机摄像头作为拍摄设备，然后将拍到的画面作为数据传输到电脑上，然后在电脑上通过驱动程序进行处理并给出反馈。于是我们着手于寻找可以实时识别画面的，将手机变成电脑摄像头的软件，于是我们找到了Iriun Webcam这个软件，将软件调试成功后，根据这个软件修改程序以适配运行，并成功同步完成一人持手机拍摄，一人于电脑上运行程序并同时给出程序的指令反馈。
3.针对遇到墙壁和桌子无反馈的问题，我们讨论后认为应该是问题根源是：一，对于创意化非传统式的桌子，程序的识别经常性的出错。二，我们使用的是边缘距离测算算法来对出现的画面进行判断和处理，但是这里的白墙是模型无法识别的。这两个原因导致当底部的画面中桌子的轮廓并不能让程序识别的情况下，程序认为前方是可以行走的区域，但这是错误的。这些原因也导致了其他的问题，而对于这个缺陷，我们的解决方案是变更模型，从nano变为s，在变化前后的体验对比也让我们感受到了算力的重要性。
4.针对突然的左右闪躲指令以及无法给出上下台阶的指令的问题，我们讨论认为这个是因为摄像头的上下抖动导致了有椅子在画面里有了很快的速度变化导致程序认为需要躲闪，因为二维的视频无法分清楚是往右快速进入还是从上往下运动的问题，而台阶的上下问题一部分是因为程序无法识别台阶，一部分则也是因为二维的视频无法分辨上下运动变化的问题。（所以我们要尽量避免晃动）

（3）最大的进展
跑通了手机相机采集后电脑处理输出的回路，提升了可用性
